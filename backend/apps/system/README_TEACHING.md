# system 目录教程

## 作用

系统管理域：登录、用户、工作空间、AI 模型、助手/嵌入应用、API Key、参数和系统变量，也是认证与资源隔离的基础。

- `api/`：系统管理 HTTP 接口。
- `crud/`：持久化与业务服务。
- `middleware/`：token 解析与身份注入。
- `models/`：用户、工作空间、模型、助手等 SQLModel。
- `schemas/`：接口 DTO、权限表达式和认证结构。
- `__init__.py`：包声明。

## 核心作用：控制面

system 不生成 SQL，也不执行查询；它回答运行前的身份与资源问题：谁在请求、当前工作空间是什么、可用哪些模型/数据源、是否是嵌入助手、是否拥有资源权限。其他业务模块都依赖这些答案。

## 关键上下文

`TokenMiddleware` 解析 Header 后把用户与助手写入 request；`common/core/deps.py` 暴露 `CurrentUser` 和 `CurrentAssistant`。`CurrentUser.oid` 是多数查询的工作空间过滤条件；切换工作空间后，模型、数据源、术语、样例、看板都应改变。

## 模型与助手

模型管理保存供应商/协议/API 配置并维护工作空间映射。助手是对外嵌入/高级应用边界，可以指定模型、UI、域名、token 和外部数据源。动态数据源经 `AssistantOutDsFactory` 统一成问数能消费的 Schema/执行配置。

## 权限层次

认证确认“你是谁”；工作空间确认“你在哪个租户”；`require_permissions` 确认“你能否访问这个具体资源”；datasource 行列规则再确认“你能看哪些数据”。这四层不可互相替代。

## 修改注意

- 新增资源类型要同步权限表达式、工作空间资源查询和审计资源名。
- 敏感字段更新常用“留空表示不修改”，避免把掩码字符串覆盖到数据库。
- 删除模型前要检查默认模型、工作空间映射和助手引用。
- 嵌入 CORS 来源是动态配置，变更助手后要考虑缓存刷新。
