# terminology 目录教程

## 作用

维护业务术语、同义词和解释，让模型把“GMV、活跃客户、本财年”等业务语言映射到准确字段/计算口径。

- `api/`：术语增删改查、导入导出。
- `curd/`：持久化、embedding、相似召回、prompt 格式化和自定义提示词相关逻辑。
- `models/`：术语与相关模型。
- `__init__.py`：包声明。

## 它解决什么问题

数据库字段名只能描述技术结构，无法完整表达企业口径。术语库把自然语言中的缩写、别名、指标定义、过滤口径和时间边界补给模型。例如“复购客户”到底按订单次数、支付状态还是时间窗口计算，应在术语描述中明确。

## 数据流

管理端创建/批量导入 → 按工作空间和可选数据源保存 → 为 word/description 生成向量 → pgvector 持久化 → 问数时按 question 相似度与资源范围过滤 → 转成 `<terminologies>` 风格内容 → 加入 SQL/分析 prompt。

## 关键约束

- `oid` 防止跨工作空间召回。
- specific_ds/datasource_id 或 advanced_application 限制适用范围。
- enabled=false 的术语不应进入召回。
- 更新文本后必须重新计算 embedding，否则语义与向量不一致。

## 写好术语的方法

包含“业务名称、定义、涉及字段、必要过滤、时间口径、反例”。避免只写“GMV=成交总额”这类无法落 SQL 的循环解释。冲突口径应拆分到不同数据源/应用范围。
