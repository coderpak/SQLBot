# common/audit 目录教程

## 作用

记录“谁在什么时候对哪个资源做了什么操作”，与 LLM 的步骤日志不同：审计面向系统操作合规，ChatLog 面向一次 AI 执行过程。

- `models/`：审计日志持久化模型与枚举。
- `schemas/`：装饰器、上下文和日志辅助。
- `__init__.py`：包声明。

## 审计对象

一条系统审计通常包含用户/工作空间、模块、操作类型、资源 ID/名称、HTTP 方法和路径、请求详情、成功/失败、耗时、IP、User-Agent 和错误信息。它服务管理员追责与合规，不用于保存完整大模型 prompt。

## 装饰器流程

`@system_log(LogConfig(...))` 同时支持 async/sync 函数：绑定原函数参数 → 从表达式提取资源 ID → 执行业务 → 必要时从返回值提取新资源 ID → 获取请求上下文 → 写成功/失败日志。`result_id_expr` 常用于创建接口，`resource_id_expr` 常用于更新/删除。

## 设计注意

- 审计失败一般不应掩盖主业务结果，但也不能静默到完全不可观察。
- 密码、token、API Key、数据库配置必须脱敏。
- 装饰器与权限装饰器的先后顺序会决定拒绝请求是否记录。
- 批量操作可能有多个资源，需要资源列表而非单 ID。
