# common 目录教程

## 作用

跨业务域的基础设施。业务模块可以依赖 common，common 不应反向依赖具体页面业务。

## 文件与子目录

- `error.py`：统一业务异常，如数据库错误、解析错误、单消息错误。
- `core/`：配置、系统库 Session、依赖注入、认证安全、统一响应、缓存、分页、文件。
- `audit/`：操作审计模型、装饰器和请求上下文。
- `utils/`：加解密、embedding 线程、Excel、HTTP、国际化、ID、数据格式等纯工具。
- `__init__.py`：包声明。

## 依赖方向

`apps/*` 可以依赖 `common`；`common` 应尽量不依赖具体业务模块，否则容易形成循环导入。允许的例外要有明确原因，例如审计资源名解析需要知道部分业务模型。

## 三类基础设施

- core 管“请求如何运行”：配置、Session、依赖、认证基础、响应和缓存。
- audit 管“请求做了什么”：操作日志和请求上下文。
- utils 管“数据如何转换”：格式、向量补偿、加密、时间、ID 和纯函数。

判断代码放置位置时，先问它是否需要某个业务实体。如果需要 Chat、Datasource 或 Workspace 的具体规则，通常不应抽到通用 utils。
